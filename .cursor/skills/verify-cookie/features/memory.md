# Memory

John quits and comes back, and Cookie still knows what he said. He can ask about an old session, tell Cookie to remember or forget something, and nothing from that memory leaves the Mac.

## Sub-features

- `memory-persist` keeps the conversation after quit and relaunch. `status: verified (verify-evidence/m1-memory-persist/transcript.jsonl)`
- `memory-recall` answers story #2 from a past session. `status: planned`
- `memory-remember` stores "Remember my ECE midterm is Friday" as a pinned fact with `source_turn`, then asks in a new conversation. `status: verified (verify-evidence/m1-memory-remember/transcript.jsonl)`
- `memory-forget` drops the locker code from the assistant echo, a paraphrased profile row, the vector tables, the same conversation, a second forget's summary, and the next prompt. `status: verified (verify-evidence/m1-memory-forget/transcript.jsonl)`
- `memory-reflect` writes a journal line and facts after a session goes quiet. `status: verified (verify-evidence/m1-memory-reflect/transcript.jsonl)`
- `memory-profile-cap` keeps the stored profile at or under 800 tokens, with pinned keys kept. `status: verified (verify-evidence/m1-memory-profile-cap/transcript.jsonl)`
- `memory-rebuild` rebuilds derived memory inside the next core process and recalls it from a new conversation. `status: verified (verify-evidence/m1-memory-rebuild/transcript.jsonl)`
- `memory-embed-down` still chats and still recalls when the embedding server is gone. `status: verified (verify-evidence/m1-memory-embed-down/transcript.jsonl)`
- `memory-no-egress` keeps every memory drive on loopback with `egress = 0`. `status: planned`

## How to get to it (user POV)

- Quit Cookie and open it again, then ask about something said in the earlier conversation.
- Ask "what did I say about the ECE midterm last week?"
- Say "Remember my ECE midterm is Friday", start a new conversation, and ask about the midterm.
- Say "Forget the midterm", then ask about it again.
- Leave a session quiet long enough for a journal line to appear.
- Keep talking after a lot of memory has been stored. The profile must not crowd out the conversation.
- Throw away derived memory. Asking again still finds the fact from the raw turns.
- Chat while the embedding server is not running. A reply still arrives, and a lexical match can still be recalled.
- Use any of the paths above. Nothing from the turn leaves the Mac.

## Driving it with verify-cookie

Preconditions:

- `pnpm install` has been run at the repository root.
- `.cursor/skills/verify-cookie/bin/drive-core doctor --core real` printed `ok`, `protocolVersion 0.1`, `server cookie-core`, `runtime up Qwen3.6-35B-A3B`, `llamaPort 18080`, and `sockets loopback`.
- `COOKIE_DATA_DIR` is a new `mktemp -d /tmp/cookie-m0.XXXXXX` for the run. Never point it at John's Application Support folder.
- Evidence for a sub-feature goes in `verify-evidence/m1-<sub-feature>/`: `command.txt`, `transcript.jsonl`, and `db.txt` (a read-only dump of the relevant tables).
- Every drive below asserts `sockets loopback` and `egress = 0` on every stored turn. That assertion is `memory-no-egress`. The real-Qwen eval run checks the same.

- **Persist.** Run `.cursor/skills/verify-cookie/bin/drive-core drive memory-persist --evidence verify-evidence/m1-memory-persist --core real`. The drive uses the built-in stub on port `18080`. It sends a code word, shuts the core down, starts a new core on the same data dir, and asks for the word. The second prompt does not contain the word. Exit code is 0. Stdout contains `persist true` and `egress 0`. `db.txt` shows the `turns` rows, every `egress` is 0, and `ended_at` is null. `transcript.jsonl` has two `initialize` requests. Verified on Linux against the stub. The Mac relaunch of the app is still a later drive.
- **Recall.** Run `.cursor/skills/verify-cookie/bin/drive-core drive memory-recall --evidence verify-evidence/m1-memory-recall --core real` against a seeded fixture database. The stub records the request body, and the drive asserts the seeded turn is in the prompt. On the Mac the same drive runs against real Qwen and the answer contains the fact. Leave `memory-recall` `planned` until that evidence exists.
- **Remember.** Run `.cursor/skills/verify-cookie/bin/drive-core drive memory-remember --evidence verify-evidence/m1-memory-remember --core real`. The drive says to remember, starts a new conversation, and asks. Exit code is 0. Stdout contains `remember true`, `pinned true`, and `egress 0`. `db.txt` shows a pinned fact whose `source_turn` is that user turn. The second prompt is not required to contain the fact. Putting a remembered fact into a later prompt is `memory-recall`, and that drive is still planned.
- **Forget.** Run `.cursor/skills/verify-cookie/bin/drive-core drive memory-forget --evidence verify-evidence/m1-memory-forget --core real` with `COOKIE_REFLECT_IDLE_MS=250` and a loopback embed stub on `COOKIE_EMBED_PORT`. The stub assistant repeats the locker code. Reflect writes a profile row whose value is that code and a paraphrase `Gym locker #4417`. The drive forgets it, asks again in the same conversation, forgets a second fact in that session, then asks in a new conversation. Exit code is 0. Stdout contains `forget true`, `profile dropped`, `vectors cleared`, `prompt clean`, `same conversation clean`, and `second forget clean`. `db.txt` has the code in the raw user turn and in the assistant echo, and nowhere in facts, `facts_fts`, chunks, the summary, the journal, the profile, `vec_facts`, `vec_chunks`, or `forgotten_turns`. The paraphrase is not in the profile. The first secret is not in the summary after the second forget. The forget reply is not in `embed_index`. Neither follow-up prompt contains the code. stderr is only `memory.forget facts=<ids> turns=<ids>` lines, and those lines do not contain the code. `turns_fts` may still contain the raw text. Reflect stores `source_turns` as a JSON array. A citation may be a turn id from the capped prompt or a fact id, stored as that fact's source turn. A missing or invalid citation stores every capped prompt turn plus every shown fact's source turn. The drive does not require `source_turn` on the locker row. A row with source turns drops when any of those turns is forgotten, pinned or not. A pin with no source turns stays unless its value contains a secret number, the needle equals the value, or the needle is `my` plus the key. A bare needle equal to the key does not drop that hand pin. A name that exists only on the forgotten turn is purged. Every other fact sourced from a forgotten turn is deleted too. Fact text that equals a key or value drops an unpinned row only. A fact-path forget marks the source turn, its reply, and the request turn. It does not mark every other turn that contains the needle. A separate turn that repeats the secret stays recallable. That is a known issue, not part of this drive. A forget with no matching fact falls back to a unique earlier turn or chunk in the core tests. A user turn and its assistant reply count as one candidate. That fallback deletes facts whose source turn is one of those turns, and fact retrieval skips a fact that still cites a forgotten turn. The request turn does not count. A matching chunk marks every turn it covers. A chunk that spans the request drops secret tokens that appear only in that request. More than five distinct candidates is ambiguous and forgets nothing. This drive still forgets a stored fact, so that fallback is not marked verified here.
- **Reflect.** Run `.cursor/skills/verify-cookie/bin/drive-core drive memory-reflect --evidence verify-evidence/m1-memory-reflect --core real` with `COOKIE_REFLECT_IDLE_MS=250`. The first idle reflect is held open. The next `chat.send`, on a new conversation, aborts it. A later reflect then writes one journal row and a fact whose `source_turn` is a stored turn. Exit code is 0. Stdout contains `reflect aborted` and `journal 1`. `command.txt` records `COOKIE_REFLECT_IDLE_MS`.
- **Profile cap.** Run `.cursor/skills/verify-cookie/bin/drive-core drive memory-profile-cap --evidence verify-evidence/m1-memory-profile-cap --core real` with `COOKIE_REFLECT_IDLE_MS=250`. Reflect writes a pinned `name` and 16 unpinned notes, and the core stores the capped list. Exit code is 0. Stdout contains `profile capped` and `pinned kept`. The stored profile is at or under 800 tokens, the pinned name is `John`, and `note_15` is not in the store.
- **Rebuild.** Run `.cursor/skills/verify-cookie/bin/drive-core drive memory-rebuild --evidence verify-evidence/m1-memory-rebuild --core real` with `COOKIE_REFLECT_IDLE_MS=250`. The drive stores a turn through the core, shuts that process down, and clears derived rows. The next core process reflects the session. Recall is a new `conversationId`. Exit code is 0. Stdout contains `rebuild true` and `recall true`. The rebuilt fact's `source_turn` is the user turn, and that new conversation's prompt contains the fact.
- **Embeddings down.** Run `.cursor/skills/verify-cookie/bin/drive-core drive memory-embed-down --evidence verify-evidence/m1-memory-embed-down --core real`. The drive uses the built-in stub on port `18080` and sets `COOKIE_EMBED_PORT` to a loopback port it binds and then closes, so it does not dial `8081` or `8080`. It stores a code word in one conversation, then asks from a different conversation id. The question does not contain the word. Exit code is 0. Stdout contains `embedDown true`, `recall true`, and `egress 0`. The reply contains the word, which the stub returns only when an earlier message has it and the latest user text does not. `db.txt` shows both sessions and `egress` 0. Stderr is empty. Verified on Linux against the stub. Qwen rerank milliseconds and time to first token are not in that transcript. `pnpm --filter @cookie-agent/core bench-retrieval` prints those as `unmeasured` until a Mac chat server is already up.

## Gotchas

- `memory-persist`, `memory-remember`, `memory-forget`, `memory-reflect`, `memory-profile-cap`, `memory-rebuild`, and `memory-embed-down` are the drives above. `.cursor/skills/verify-cookie/bin/drive-core drive memory-recall --evidence /tmp/cookie-memory-evidence --core real` prints usage and exits 2. A vitest run is not feature evidence. Do not mark a sub-feature `verified` from this file alone, or from the `chat-history` transcript.
- `memory-persist` does not accept `--llama external`. It needs the built-in stub so the second reply contains the code word only when the new process loaded the stored turns.
- Core tests cover idle reflect, `memory.remember`, `memory.forget`, consolidation, and the profile cap against a fake model. They do not write `verify-evidence/`. The drives above do. `memory-recall` and `memory-no-egress` stay `planned`.
- `COOKIE_REFLECT_IDLE_MS` arms the reflect job. It does not end a session and it is not the popup's 10-minute close window. Session end is a later `chat.send` whose `conversationId` differs. `readReflectIdleMs` in `schedule.ts` is the only parser. Unset is 600000. `0` is 0. `createMemoryRuntime` returns that job as `runtime.reflector`. A new conversation cancels the timer. When `COOKIE_REFLECT_IDLE_MS` is a non-empty string, `ChatLog.beginAndReflect` awaits that same reflector before the next retrieval. The memory-reflect drive still aborts the idle job with `chat.send`.
- `drive-core` does not launch the Mac app. The Mac half of recall, against real Qwen, is a later `drive-mac` or real-core run from a fresh temp data dir.
- Do not use port `8080`. Verification uses `COOKIE_LLAMA_PORT=18080`.
- Do not point `COOKIE_DATA_DIR` at `~/Library/Application Support/com.johnkimec.cookie-agent`. Under `VITEST` or `NODE_ENV=test` (any case) the core throws instead of opening that default directory, on every OS. A symlink or other path with the same device and inode is the same directory. `HOME` selects that home. A missing folder is compared from its nearest existing parent, case-insensitively on darwin. Tests point `HOME` at a temp directory. A test that starts a core sets its own temp directory and deletes it afterwards. Env is read before `cookie.db` is opened.
- `memory-no-egress` is not a separate drive. It is the loopback and `egress = 0` assertion on every drive above, plus the real-Qwen eval run.
- `pnpm eval memory --fake` replays `evals/memory-recall/tasks/` (03–12) through the real core over stdio and scores BM25 retrieval: an `expectedIds` turn in the top 8, with no `distractorIds` turn above it, and every `requiredIds` turn in that top 8. A required id is checked against its own `requiredFacts` entry, not `expectedFact`. Task 08 has no accept entry; both Marcus intro turns require `Marcus Lee`. Task 11 lists only the turns that carry the string. `04-knee-squat-swap` is real-only and is left out of that denominator. CI runs that command and exits 1 below 8/9. It does not mark `memory-recall` verified. Samples 01 and 02 are in `evals/memory-recall/examples/` and are not scored. `pnpm eval memory --real` is the Mac score and requires `--llama-port` and `--embed-port`, or `COOKIE_LLAMA_PORT` and `COOKIE_EMBED_PORT`. It does not default to 8080 or 8081. Fixture assistant lines go through the scripted stub. A reflect prompt is answered with empty JSON, so `--real` does not test fact extraction. The final question goes to the real model at temperature 0. The fake bar is 8/9. `06-forget-debt-to-daniel` still runs and still counts. It passes only when `forgottenTurnIds()` includes the debt turn, and it is known-blocked while that method is missing. An `open()` throw on a corrupt `cookie.db`, or a non-array return, is an error on task 06. Only a missing method is known-blocked. The core prints `cookie-core: loopback guard active <nonce>` only after the guard refuses `192.0.2.1`. The runner requires that exact line. A space is removed only before `g`, `kg`, `lb`, `ml`, `am`, `pm`, or `%`, so `170 g` matches `170g` and `170 g.`, and does not match inside `1170 g`, `1,170 g`, `1.170 g`, or `170 grams`. `2 kg` does not match `4.2 kg`, and `5 kg` does not match `0.5 kg`. `10:30` still matches `10:30 in the morning` and `10:30 a.m.`, and `Bahen` still matches `at 3 Bahen`. Reflect gives up after 30 seconds and the chat continues. Evidence under `verify-evidence/m1-recall/` is gitignored and is not a drive transcript.
- `COOKIE_REFLECT_IDLE_MS` (the eval sets `0`) makes `ChatLog` await `runtime.reflector` when a new `conversationId` ends the previous session, before that turn is retrieved. That is the shared `LocalReflector`. `COOKIE_LOOPBACK_ONLY=1` fails a TCP connect whose host is not `127.0.0.1` or `::1`.
- Protocol stays `0.1`. There is no memory viewer in M1. Forgetting is something John says. `pnpm memory dump` is the read-only look at `cookie.db`. It is not a drive. `db.txt` in the persist evidence is that dump.
- A new chat is a different `conversationId` on `chat.send`. The app also mints a new id after the popup has been closed for 10 minutes. The core does not time that window and protocol 0.1 has no message for it. `shutdown` does not end the session.
- Turns and facts are embedded after a turn is stored, and only when the embedding server's `/health` on `127.0.0.1:$COOKIE_EMBED_PORT` (default 8081) is up. A down server writes no new vectors and prints no stderr. Retrieval then uses BM25 only. One pass embeds about 64 chunks and commits each batch on its own. A throw while deleting a dead fact vector is logged and indexing continues. A turn that fails to embed three times in this process is skipped so a later turn still indexes, and facts still index after a turn failure. A fact with `superseded_by` set, or `valid_until` at or before now, is not embedded, and `VectorIndex.delete` removes its vector. `pendingTurns` skips a forgotten turn with one `NOT EXISTS` on `forgotten_turns.turn_id`. `pnpm --filter @cookie-agent/core check-embed` is the Mac check against a real nomic server. The model file is `nomic-embed-text-v1.5.Q8_0.gguf`. The documented llama-server command includes `--embeddings --pooling mean`. `pnpm --filter @cookie-agent/core bench-retrieval` times local retrieval and prints Qwen rerank and time-to-first-token as `unmeasured` unless chat `/health` is already up. Neither script is CI, and neither starts `llama-server`.
- Default RRF weights are vector 1 and BM25 1. `COOKIE_RRF_VECTOR` and `COOKIE_RRF_BM25` override them. Retrieval calls `forgottenTurnIds()` when the store object has that method. It is not on `MemoryStore`. `SqliteMemoryStore` has it. Turns, chunks, session summaries, and facts whose `source_turn` is forgotten are dropped before fusion. `ChatLog.messagesFor` skips forgotten turns, keeps the newest 20 live turns, stores the request turn, and passes that id in `retrieve(query, signal, omitTurnIds)`. The forget drive asserts the same-conversation ask, the second forget, and the reworded profile do not leak the code.
- Query embeds use `COOKIE_EMBED_QUERY_TIMEOUT_MS` (default 400 ms) and fall back to BM25 if that elapses. `COOKIE_EMBED_TIMEOUT_MS` is a deprecated alias for that query budget only. Index embeds use `COOKIE_EMBED_INDEX_TIMEOUT_MS` (default 10 s). Every env value is read before `cookie.db` opens. `COOKIE_RERANK` is off unless set to `1`. Rerank then asks for at most 8 candidate indices under a JSON schema (`maxItems` 8), with `max_tokens` 64 and 100-character previews of the matching chunk when a hit is a chunk. The chat abort signal is passed into rerank, and an aborted signal after rerank returns no hits. Turns already in recent history, including the request turn, are dropped before the top 8. Each retrieved line shows the local date from `localDay(ms, readTimeZone(env))` and, for a long turn, a window centered on a whole-word match (stopwords and tokens under 3 characters skipped; a token that contains a digit wins, then the rarer token by `turns_fts` row count, then the longer token). The BM25 `MATCH` drops those stopwords and tokens under 2 characters. Embedder HTTP 429 and 503 do not spend an index attempt. Cut edges snap to whole code points. Chunk hits `${turnId}#n` are fused as `turnId`. kNN `k` stays at or below 4096.
