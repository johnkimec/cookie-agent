# Chat streaming

John sends a message from the popup and sees Cookie's reply arrive in more than one piece, labelled on-device. He can stop a reply that is still arriving.

## Sub-features

- `chat-send-stream` sends one message and receives the reply as more than one `chat.delta`, then `chat.done` with `finishReason` `stop`. `status: verified (verify-evidence/m0-real-chat-streaming/transcript.jsonl)`
- `chat-cancel` stops an in-flight reply. `chat.done` uses `finishReason` `cancelled` and no further deltas arrive. `status: verified (verify-evidence/m0-real-chat-streaming/transcript.jsonl)`
- `chat-stop` turns the send control into Stop while a reply is arriving. Return and that control send one `chat.cancel`. Escape stops the reply and leaves the panel open; Escape again, once nothing is streaming, closes the panel. The partial reply stays on screen. `status: planned`
- `chat-history` asks for a code word in one turn and repeats it in a second turn of the same conversation. The second prompt does not contain the word. `status: verified (verify-evidence/m0-chat-history/transcript.jsonl)`
- `chat-popup-reply` shows the `you` turn and the `cookie` turn arriving in chunks. The on-device state is one dot in the input row, not a pill on the reply. `status: planned`
- `chat-popup-wrap` shows the full multi-paragraph reply. The accessibility value of `cookie.turn.cookie.0` is the raw model text, and the row is taller than one line. `status: planned`
- `chat-popup-follow` keeps the bottom anchor inside the window when the transcript overflows, and does not yank the view down if the user has scrolled up. `status: planned`
- `chat-popup-markdown` renders emphasis, inline code, fenced code, lists, and links in a cookie reply while chunks are still arriving. `\( ... \)` stays inline math and `\[ ... \]` is shown as display math. `status: planned`
- `chat-real-runtime` runs the Mac app against the real core and `llama-server`, waits until the runtime is up, and shows a non-empty reply that is not the fake-core sentence. Verified by Sergey on the Mac, 2026-10-25, commit c89adc6. `status: verified (verify-evidence/m0-mac-real/)`
- `chat-talking-pose` shows Cookie in the Talking pose while chunks arrive, or the static mouth-open pose when Reduce Motion is on. `status: planned`
- `chat-session-expiry` starts a new conversation on the next send after the popup has been closed for the draft window (10 minutes). ⌘K starts a new conversation too. Opening the popup again does not drop a reply that is still arriving. `status: planned`

## How to get to it (user POV)

- Open the popup (⌥Space or `Ask Cookie…`).
- Type in the field labelled `Ask Cookie…` and press Return.
- Watch the reply grow before it finishes.
- While the reply is still arriving, the ⏎ control reads Stop (`cookie.popup.stop`). Press Return or Stop. The partial reply stays, and the control returns to ⏎.
- Press Escape while the reply is arriving. The reply stops and the panel stays open. Press Escape again after it has stopped. The panel closes.
- Press ⌘K. The field clears and the next message is a new conversation.
- Close the popup and leave it closed for 10 minutes. The next message is a new conversation. Opening it sooner keeps the same conversation. Opening it while a reply is still arriving leaves that reply on screen.

## Gotchas

- The fake reply and the real-core stub reply are canned text, not a model answer. Assert the chunks and `finishReason`, not that the words answer the question. The real-core joined text is `Hello. This reply is from the local stub, on device.` The fake joined text is the canned fake sentence.
- `--llama stub` is the default. `--core real` without `--llama external` still binds a stub on `127.0.0.1:18080` and cannot grade a real model. `--llama external` binds nothing and uses `COOKIE_LLAMA_PORT` (the product default `8080` when that variable is unset). `chat-history` refuses to run without `--llama external`.
- The second history prompt must not contain `marmalade417`. A reply that only echoes the latest prompt is not proof of history. Time to first token is measured from the `chat.send` write to the first `chat.delta`. A cold load may sit in `loading` or `down` until the watch sees `up`. That wait is 120 seconds. Each chat may take up to 180 seconds per line.
- Node 22.13 prints `ExperimentalWarning: Type Stripping is an experimental feature and might change at any time` on the core child's stderr, then a line about `--trace-warnings`. Doctor and this drive exit 1 when stderr is non-empty. `drive-core`, `pnpm core`, and `pnpm fake-core` pass `--disable-warning=ExperimentalWarning`. That warning has no code, so the type is the narrowest flag. Do not drop the empty-stderr check and do not pass `--no-warnings`. A launch this repo does not own can set `NODE_OPTIONS=--disable-warning=ExperimentalWarning`. The Swift app's default command is `pnpm --filter @cookie-agent/core fake-core`, so it picks up the flag from `core/package.json`. Node older than 22.6 cannot strip types. `.nvmrc` is `22`. `engines` is `>=22.6`.
- Default `COOKIE_THINKING` is off. A real Qwen server still needs `chat_template_kwargs.enable_thinking` false on the request, or the reply can spend the turn in thinking and miss the code word. The request-body pin is the vitest in `core/src/llama.test.ts`. This transcript does not show the HTTP body.
- A cancelled real-core reply reports usage `{ inputTokens: 0, outputTokens: 0 }`. The stub closes the HTTP request (`modelAborted true`) and does not return a partial token count. Usage after a cancel is best-effort and may be zero. Do not require an estimated token count.
- A model completion that succeeds with no text is `chat.done` with `finishReason` `stop` and no `chat.delta`. Delta `text` still has minLength 1, so the core does not emit an empty chunk. `finishReason` `error` is a failed stream, including one that produced no text. It is not used for an empty success.
- `on-device` is the label and tooltip of the single input-row indicator `cookie.badge.on-device`. Do not require a pill on each reply, and do not require the longer privacy sentence `On-device. Nothing left your Mac.` on this surface.
- The wireframe labels the turns `you` and `cookie` in lowercase.
- One in-flight reply. A second `chat.send` before `chat.done` is an error, not a second stream. The popup's Return during that reply sends `chat.cancel`, not a second `chat.send`.
- While a reply is arriving, Escape stops it and leaves the panel open. Escape closes the panel only when nothing is streaming. A second stop does not send a second `chat.cancel`. Clicking outside still closes without cancelling.
- A new conversation is a new `conversationId` on `chat.send`. The core treats that id as the session. Closing the popup does not by itself start one. The next send does, once the popup has been closed for the draft window. ⌘K starts one immediately. `COOKIE_DRAFT_TTL_SECONDS` can only shorten that window.
- A cancel result is applied on the main queue after buffered `chat.delta` chunks. Settling first drops the tail, because `applyDelta` no-ops once the reply is no longer in flight.
- Display math may span lines (`\[` then a later `\]`). That whole block becomes `$$`. A fence, or a missing `\]`, leaves the characters as written.
- `package-app.sh` copies `iosMath_iosMath.bundle`, `HighlightSwift_HighlightSwift.bundle`, and `SwiftStreamingMarkdown_SwiftStreamingMarkdown.bundle` into `Contents/Resources`. The markdown `.xcassets` still compile with `actool`.
- Do not mark the popup sub-features verified from this transcript. The transcript never opened a window.
- `drive-core drive` without `--evidence <dir>` prints its usage and exits 2.
- `drive-mac chat --runtime real` needs a new `mktemp -d /tmp/cookie-m0.XXXXXX` and a shell with no leftover `COOKIE_*` variables on every run. A reused data directory carries the last run's pid files.
